# JavaScript 继承方式演进历史

## 前言

JavaScript 的继承机制经历了从 ES5 到 ES6+ 的演进，每种新的继承方式都是为了解决前一种方式存在的问题。让我们来看看这个演进过程。

## 1. 原型链继承（最早期）

### 基本实现

```js
function Animal(name) {
    this.name = name;
    this.colors = ['red', 'blue', 'green'];
}

function Dog() {
    this.bark = function() {
        console.log('汪汪汪');
    }
}

Dog.prototype = new Animal('animal');
var dog1 = new Dog();
var dog2 = new Dog();

dog1.colors.push('black');
console.log(dog1.colors); // ['red', 'blue', 'green', 'black']
console.log(dog2.colors); // ['red', 'blue', 'green', 'black']
```

### 解决的问题

- 实现了基本的继承关系
- 子类可以访问父类的方法和属性

### 存在的问题

1. **引用类型属性共享**：所有实例共享同一个引用类型属性
2. **无法向父类传参**：创建子类实例时无法向父类构造函数传递参数
3. **原型链过长**：多层继承时原型链会变得很长，影响性能

---

## 2. 借用构造函数继承（Constructor Stealing）

### 基本实现

```js
function Animal(name) {
    this.name = name;
    this.colors = ['red', 'blue', 'green'];
}

function Dog(name) {
    Animal.call(this, name); // 借用父类构造函数
    this.bark = function() {
        console.log('汪汪汪');
    }
}

var dog1 = new Dog('dog1');
var dog2 = new Dog('dog2');

dog1.colors.push('black');
console.log(dog1.colors); // ['red', 'blue', 'green', 'black']
console.log(dog2.colors); // ['red', 'blue', 'green', 'red']
```

### 解决的问题

1. **引用类型属性独立**：每个实例都有自己独立的引用类型属性
2. **可以向父类传参**：子类构造函数可以向父类构造函数传递参数

### 存在的问题

1. **方法无法复用**：父类的方法无法被复用，每个实例都会创建新的方法
2. **无法继承原型方法**：只能继承父类构造函数中的属性和方法，无法继承原型上的方法

---

## 3. 组合继承（Combination Inheritance）

### 基本实现

```js
function Animal(name) {
    this.name = name;
    this.colors = ['red', 'blue', 'green'];
}

Animal.prototype.sayName = function() {
    console.log('My name is ' + this.name);
}

function Dog(name) {
    Animal.call(this, name); // 借用构造函数
    this.bark = function() {
        console.log('汪汪汪');
    }
}

Dog.prototype = new Animal(); // 原型链继承
Dog.prototype.constructor = Dog; // 修复构造函数指向

var dog1 = new Dog('dog1');
var dog2 = new Dog('dog2');

dog1.colors.push('black');
console.log(dog1.colors); // ['red', 'blue', 'green', 'black']
console.log(dog2.colors); // ['red', 'blue', 'green', 'red']
dog1.sayName(); // My name is dog1
```

### 解决的问题

1. **结合了两种继承的优点**：既解决了引用类型属性共享问题，又实现了方法复用
2. **可以向父类传参**：子类构造函数可以向父类构造函数传递参数
3. **方法可以复用**：父类原型上的方法可以被复用

### 存在的问题

1. **父类构造函数被调用两次**：一次在创建子类原型时，一次在子类构造函数中
2. **性能问题**：父类构造函数被调用两次，造成不必要的性能开销

---

## 4. 原型式继承（Prototypal Inheritance）

### 基本实现

```js
function object(o) {
    function F() {}
    F.prototype = o;
    return new F();
}

var person = {
    name: 'Nicholas',
    friends: ['Shelby', 'Court', 'Van']
};

var anotherPerson = object(person);
anotherPerson.name = 'Greg';
anotherPerson.friends.push('Rob');

var yetAnotherPerson = object(person);
yetAnotherPerson.name = 'Linda';
yetAnotherPerson.friends.push('Barbie');

console.log(person.friends); // ['Shelby', 'Court', 'Van', 'Rob', 'Barbie']
```

### 解决的问题

1. **简单易用**：不需要创建构造函数，直接基于对象创建新对象
2. **适合简单场景**：适合只需要继承一个对象，而不需要创建构造函数的情况

### 存在的问题

1. **引用类型属性共享**：所有实例共享同一个引用类型属性
2. **无法向父对象传参**：创建新对象时无法向父对象传递参数

---

## 5. 寄生式继承（Parasitic Inheritance）

### 基本实现

```js
function createAnother(original) {
    var clone = object(original); // 通过调用函数创建一个新对象
    clone.sayHi = function() { // 以某种方式来增强这个对象
        console.log('hi');
    };
    return clone; // 返回这个对象
}

var person = {
    name: 'Nicholas',
    friends: ['Shelby', 'Court', 'Van']
};

var anotherPerson = createAnother(person);
anotherPerson.sayHi(); // 'hi'
```

### 解决的问题

1. **增强对象**：可以在继承的基础上为对象添加新的方法或属性
2. **灵活性**：可以根据需要动态地为对象添加功能

### 存在的问题

1. **引用类型属性共享**：所有实例共享同一个引用类型属性
2. **无法向父对象传参**：创建新对象时无法向父对象传递参数
3. **方法无法复用**：每个实例都会创建新的方法

---

## 6. 寄生组合式继承（Parasitic Combination Inheritance）

### 基本实现

```js
function inheritPrototype(subType, superType) {
    var prototype = Object.create(superType.prototype); // 创建对象
    prototype.constructor = subType; // 增强对象
    subType.prototype = prototype; // 指定对象
}

function Animal(name) {
    this.name = name;
    this.colors = ['red', 'blue', 'green'];
}

Animal.prototype.sayName = function() {
    console.log('My name is ' + this.name);
}

function Dog(name) {
    Animal.call(this, name); // 借用构造函数
    this.bark = function() {
        console.log('汪汪汪');
    }
}

inheritPrototype(Dog, Animal); // 寄生组合式继承

var dog1 = new Dog('dog1');
var dog2 = new Dog('dog2');

dog1.colors.push('black');
console.log(dog1.colors); // ['red', 'blue', 'green', 'black']
console.log(dog2.colors); // ['red', 'blue', 'green', 'red']
dog1.sayName(); // My name is dog1
```

### 解决的问题

1. **父类构造函数只调用一次**：解决了组合继承中父类构造函数被调用两次的问题
2. **性能优化**：减少了不必要的函数调用，提高了性能
3. **保持了所有优点**：既解决了引用类型属性共享问题，又实现了方法复用

### 存在的问题

1. **代码复杂**：需要额外的辅助函数来实现继承
2. **理解困难**：对于初学者来说，理解起来比较困难

## 7. ES6 Class 继承

### 基本实现

```js
class Animal {
    constructor(name) {
        this.name = name;
        this.colors = ['red', 'blue', 'green'];
    }
    
    sayName() {
        console.log('My name is ' + this.name);
    }
}

class Dog extends Animal {
    constructor(name) {
        super(name); // 调用父类构造函数
        this.bark = function() {
            console.log('汪汪汪');
        }
    }
}

const dog1 = new Dog('dog1');
const dog2 = new Dog('dog2');

dog1.colors.push('black');
console.log(dog1.colors); // ['red', 'blue', 'green', 'black']
console.log(dog2.colors); // ['red', 'blue', 'green', 'red']
dog1.sayName(); // My name is dog1
```

### 解决的问题

1. **语法简洁**：使用 `extends` 关键字，语法更加简洁明了
2. **内置 super**：内置 `super` 关键字，调用父类构造函数和方法更加方便
3. **更好的封装**：支持私有字段、静态方法等现代特性
4. **类型检查友好**：对 TypeScript 等类型系统更加友好

### 优势

1. **语法糖**：本质上仍然是基于原型的继承，但语法更加清晰
2. **向后兼容**：与 ES5 的继承方式完全兼容
3. **工具支持**：现代开发工具对 class 语法支持更好

---

## 总结

### 演进脉络

1. **原型链继承** → 解决基本继承需求
2. **借用构造函数继承** → 解决引用类型属性共享和传参问题
3. **组合继承** → 结合两种继承方式的优点
4. **原型式继承** → 简化对象创建过程
5. **寄生式继承** → 增强继承对象的功能
6. **寄生组合式继承** → 优化组合继承的性能问题
7. **ES6 Class 继承** → 提供更简洁的语法和更好的开发体验

### 核心问题解决

- **引用类型属性共享**：通过借用构造函数解决
- **方法复用**：通过原型链继承解决
- **性能优化**：通过寄生组合式继承解决
- **语法简化**：通过 ES6 Class 解决

### 现代开发建议

- **新项目**：优先使用 ES6 Class 继承
- **老项目维护**：可以继续使用寄生组合式继承
- **特殊需求**：根据具体需求选择合适的继承方式
