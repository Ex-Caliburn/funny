# 虚拟滚动（Virtual Scrolling）实践场景

## 什么是虚拟滚动

虚拟滚动是一种性能优化技术，只渲染可见区域的 DOM 元素，而不是渲染整个列表。通过动态创建和销毁 DOM 元素，大幅减少内存占用和渲染时间。

## 核心原理

```
总数据：10000 条
可见区域：10 条
实际渲染：10-20 条（包含缓冲区）
```

通过计算滚动位置，动态显示对应索引的数据，保持滚动条高度为总数据高度。

## 常见应用场景

### 1. 大数据表格（Table）⭐⭐⭐⭐⭐

**场景**：
- 数据导出列表（上万条记录）
- 日志查看器
- 数据管理系统
- Excel 在线预览

**特点**：
- 列数固定，行数动态
- 需要支持排序、筛选
- 需要保持滚动位置

**实践案例**：
- **Element UI Table**：`el-table` 支持虚拟滚动（`v-loading` + 自定义）
- **Ant Design Table**：`virtual` 属性
- **AG Grid**：企业级表格，原生支持虚拟滚动
- **React Window**：专门用于虚拟滚动的库

**代码示例**：
```vue
<!-- Element UI 虚拟表格 -->
<el-table
  :data="tableData"
  height="500"
  :row-height="50"
  virtual-scroll
>
  <el-table-column prop="name" label="名称" />
  <el-table-column prop="date" label="日期" />
</el-table>
```

- 评论列表

**特点**：
- 单列或多列布局
- 需要保持滚动位置
- 需要支持下拉刷新、上拉加载

**实践案例**：
- **微信聊天**：只渲染可见的消息气泡

- **GitHub Issues**：评论列表虚拟滚动
- **React Virtualized**：Facebook 开源

**代码示例**：

**实践案例**：

**代码示例**：
```javascript

  container: grid,
  itemHeight: 250, // 每个图表卡片高度
  buffer: 2, // 上下各多渲染 2 个

    // 只渲染可见区域的图表
    return createChartCard(data[index]);
  }
});
```

## 实现要点

### 1. 计算可见范围
```javascript
function getVisibleRange(scrollTop, itemHeight, containerHeight, totalItems) {
  const start = Math.floor(scrollTop / itemHeight);
  const end = Math.min(
    start + Math.ceil(containerHeight / itemHeight) + 1,
    totalItems
  );
  return { start, end };
}
```

### 2. 保持滚动条高度
```javascript
const totalHeight = totalItems * itemHeight;
container.style.height = totalHeight + 'px';
```

### 3. 动态渲染
```javascript
function renderItems(start, end) {
  // 销毁不可见的
  // 创建可见的
  for (let i = start; i < end; i++) {
    createItem(data[i], i);
  }
}
```

### 4. 滚动事件优化
```javascript
// 使用 requestAnimationFrame 节流
let rafId = null;
container.addEventListener('scroll', () => {
  if (rafId) return;
  rafId = requestAnimationFrame(() => {
    updateVisibleRange();
    rafId = null;
  });
});
```

## 性能对比

| 数据量 | 无优化 | 虚拟滚动 | 提升 |
|--------|--------|---------|------|
| 1000 条 | 500ms | 50ms | 10x |
| 10000 条 | 5s | 50ms | 100x |
| 100000 条 | 50s+ | 50ms | 1000x+ |

## 注意事项

1. **固定高度**：虚拟滚动通常需要固定或可计算的项目高度
2. **动态高度**：如果高度不固定，需要动态计算，复杂度增加
3. **滚动位置**：需要正确计算和保持滚动位置
4. **缓冲区**：上下各多渲染几个项目，提升滚动体验
5. **状态管理**：需要正确管理可见项目的状态

## 何时使用虚拟滚动

### ✅ 适合使用
- 数据量 > 1000 条
- 列表项渲染成本高（包含图表、复杂组件）
- 需要流畅滚动体验
- 内存受限环境

### ❌ 不适合使用
- 数据量 < 100 条
- 列表项高度不固定且差异大
- 需要精确的 DOM 操作
- 项目复杂度低，性能已足够

## 与懒加载的区别

| 特性 | 懒加载 | 虚拟滚动 |
|------|--------|---------|
| DOM 数量 | 所有项目都在 DOM 中 | 只渲染可见项目 |
| 内存占用 | 较高 | 很低 |
| 实现复杂度 | 简单 | 较复杂 |
| 适用场景 | 图片、图表 | 长列表、表格 |
| 滚动性能 | 一般 | 优秀 |

## 实践建议

1. **优先使用成熟库**：不要重复造轮子
2. **结合懒加载**：虚拟滚动 + 懒加载效果更好
3. **测试大数据量**：确保在真实数据量下性能良好
4. **考虑移动端**：移动端性能更敏感
5. **提供降级方案**：不支持虚拟滚动时回退到分页
