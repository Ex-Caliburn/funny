在 ECharts 中，**Canvas** 是默认的渲染器（Renderer）。相比于另一种可选的 SVG 渲染模式，Canvas 在**大数据量渲染**、**动画性能**和**内存占用**上有着显著的提升。

以下是 Canvas 渲染模式（及默认配置）带来的核心提升点分析：

### 1. 渲染性能与大数据量处理 (Performance)

这是 Canvas 最明显的优势。

* **无 DOM 操作开销：**
* **Canvas:** 是基于位图（Bitmap）的。无论图表中有多少数据点（例如 10 万个散点），在浏览器中它只占用**一个** `<canvas>` DOM 节点。绘制 10 万个点只是在画布上改变像素颜色。
* **SVG:** 是基于矢量图的。每个数据点都是一个独立的 DOM 节点（如 `<path>` 或 `<rect>`）。渲染 10 万个点意味着浏览器要维护 10 万个 DOM 节点，这会导致极其严重的性能下降和页面卡顿。

* **批量绘制：** Canvas 可以通过一条指令绘制成千上万个相似的图形，极大地利用了 GPU 加速（虽然 Canvas 2D 主要依赖 CPU，但浏览器底层会对 Canvas 做硬件加速优化）。

> **提升点：** 在折线图（Line）、散点图（Scatter）、热力图（Heatmap）等涉及成千上万数据点的场景下，Canvas 能够实现**毫秒级**的渲染，而 SVG 可能会直接导致浏览器崩溃。

### 2. 交互与重绘效率 (Interaction & Repaint)

ECharts 底层依赖渲染引擎 **ZRender**，它对 Canvas 做了大量优化，特别是在图表交互时。

* **脏矩形渲染 (Dirty Rectangle Rendering)：**
* 当你在图表上移动鼠标（触发 tooltip）或进行局部高亮时，ECharts 不需要重绘整个画布。
* Canvas 模式下，ECharts 会计算出发生变化的区域（即“脏矩形”），只清除并重绘这一小块区域。
* **提升：** 这使得包含大量数据的图表在交互时依然能保持高帧率（FPS），鼠标跟随非常流畅。

* **增量渲染 (Incremental Rendering)：**
* 对于超大数据量，Canvas 支持分片渲染，避免长时间占用主线程导致页面“假死”。

### 3. 内存占用 (Memory Usage)

* **Canvas:** 内存占用主要取决于画布的尺寸（分辨率），而与数据量的关系相对较小。绘制 10 个点和 1000 个点，Canvas 占用的内存差异不大（主要是像素数据）。
* **SVG:** 内存占用与数据量成正比。数据越多，DOM 对象越多，内存占用呈线性甚至指数级增长。

> **提升点：** 在移动端或低性能设备上展示复杂图表时，Canvas 能有效避免内存溢出（OOM）。

### 4. 特效与可视化能力 (Visual Effects)

某些特定的可视化效果只能或更适合在 Canvas 下实现：

* **粒子动画与特效：** 如带有尾迹的特效散点图、流光效果等。
* **热力图 (Heatmap)：** 基于像素混合的渲染，Canvas 是唯一选择。
* **ECharts GL:** 虽然 GL 是基于 WebGL，但它与 Canvas 2D 的管线更亲近，通常不与 SVG 混用。

---

### 对比总结：什么时候该用 Canvas？

| 特性 | Canvas (默认) | SVG |
| --- | --- | --- |
| **数据量** | **极大 (万级以上)** | 小 (千级以下) |
| **内存占用** | 低 (由屏幕尺寸决定) | 高 (随数据量增长) |
| **渲染原理** | 像素 (位图) | 矢量 (DOM) |
| **清晰度** | 放大后会失真 (除非重绘) | **任意缩放不失真 (真矢量)** |
| **适用场景** | 大屏数据、热力图、高频刷新 | 移动端报表、PDF导出、简单饼图 |

### 什么时候 SVG 反而更好？

虽然 Canvas 是默认且性能最强的，但在以下场景 SVG 会有“提升”：

1. **高分辨率屏幕 (Retina/4K)：** SVG 天生是矢量的，不会像 Canvas 那样在浏览器缩放或高分屏下出现锯齿或模糊。
2. **低数据量的移动端页面：** 如果图表很简单（如一个只有 5 个数据的饼图），Canvas 的初始化开销可能比 SVG 大，且 SVG 的 DOM 即使在低端安卓机上也能保证绝对清晰。
3. **无障碍访问 (Accessibility)：** SVG 节点可以被屏幕阅读器读取，而 Canvas 只是一个图片黑盒。

### 如何切换？

如果你发现默认的 Canvas 在你的场景下（比如大屏文字模糊）不够好，可以强制切换为 SVG：

```javascript
// 使用 SVG 渲染器
var chart = echarts.init(container, null, { renderer: 'svg' });

// 使用 Canvas 渲染器 (默认，无需显式声明)
var chart = echarts.init(container, null, { renderer: 'canvas' });

```
